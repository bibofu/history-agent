# v13 真实 LLM 回答评测基线

本基线使用生产问答入口 `answer_question`，完整执行查询规划、结构化路由或混合检索、
`grounded-answer-v13` 生成及确定性引用校验。语义引文裁判只在离线评测中执行，不进入
线上回答链路，也不计入端到端问答延迟。

## 运行方式

```powershell
.\.venv\Scripts\history-agent.exe eval answers --top-k 10 --with-llm
```

`--with-llm` 默认启用语义引文裁判；如只需复现旧口径，可显式传入
`--no-semantic-judge`。详细 JSON 和逐题回答保存在 `data/reports/answer_eval_latest.json`，
带运行 ID 的报告不会被后续运行覆盖。

## 题集变化

回答题集由 42 题扩展为 47 题，当前综合评测集共 105 题。本轮新增：

- 3 道复杂问题：长征全程、周恩来 1954—1956 年经历、遵义会议与庐山会议比较；
- 2 道交集负例：会议列席或谈判参与不能推断共同指挥，名单共现不能推断共同任职；
- 6 条语义引文校准样本：直接支持、人名错配、共现误推互动、年份错配、审慎限定和
  因果增强。

必要事实覆盖率现在检查最终回答正文，而不是仅检查召回的证据包。逐题结果同时保存
回答正文、引文原文、章节、页码、规划与生成 Token、生成降级状态和端到端耗时。

## 语义裁判口径

语义裁判使用 `deepseek-v4-pro`，只判断回答中带引文的事实主张是否由对应摘录直接支持。
它明确禁止把姓名共现升级为互动、把名单共现升级为同一职务、把时间先后升级为因果。
裁判返回 `fail` 时必须逐字复制回答中的错误主张；若错误主张不存在于回答正文，结果无效
并自动重试一次。

校准集结果为 6/6，覆盖率和准确率均为 100%。校准集规模仍小，且回答与裁判使用同一
模型供应商，因此语义指标是可重复的自动审计信号，不代替人工史料复核。

## 当前结论

v13 已做到所有有证据回答都经过 LLM、格式引用校验稳定、拒答稳定，复杂问题的关键页召回
也能覆盖多个阶段。但真实链路仍有三类明确缺陷：精确结构化路由会在数据库记录不足时
直接截断检索回退；最终回答会把相邻或同主题引文挂到更强的事实主张上；召回到证据不等于
最终回答覆盖了必要事实。后续优化应以本运行 ID 和题集 SHA 为基线，分别修复这三类问题。
