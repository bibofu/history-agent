# 引用校验误判与诊断

## 报告与已确认问题

用户在询问“介绍一下开国大典的情况”时看到 `citation_repair_uncited_core_claim`。这个代码表示首次生成被判有事实缺少引用，模型修复一次后仍未通过；它不表示 DeepSeek 网络连接失败或本地完全没有相关文献。

本地关键词检索能召回开国大典相关片段。旧服务日志没有保存被拒绝的具体语句，因此无法还原这次生成，也不能据此统计真实失败率。以下问题通过独立构造的本地回答复现，并非该次模型回答的记录：

- `> 周恩来参加会议。` 与下一行 `> [E1]` 被拆成两个校验块。
- 事实正文与独立成段的 `[E1]` 被分开，未识别紧邻的引用。
- 嵌套列表的主题标签“共同参加会议”被要求单独引用。
- “现有资料不足以确认两人是否共同参与了其他活动”被关键词规则误判为事实陈述。

## 修复后的边界

使用已在依赖锁中存在的 markdown-it-py 解析 CommonMark 与表格结构，并声明为直接依赖。引用块和自然换行保持在同一段；独立引用段只归属同一容器中紧邻的上一段，不能跨标题、分隔线、引用块或列表项借用。表格逐行检查，不使用整张表的任意引用覆盖全部行。

只对明确的主题标签和纯粹“资料不足以确认”等说明免除引用要求。资料限制中额外夹带的事实仍需引用；标题、加粗文本或冒号结尾也不能隐藏具体历史陈述。未知证据编号、文献名或 PDF 页码不匹配仍会失败。

提示词升级为 `grounded-answer-v7`：只给有原文支持的事实补引用，无法支持的事实须删除，不能随意添加编号。仍最多修复一次。校验属于格式、引用覆盖及元数据检查，不等于对历史结论进行完整语义核实。

同步 JSON 和流式 SSE 的最终响应都保留 `llm_error_code` 与最后一次校验的 `uncited_claims`。页面将失败语句放在默认折叠的诊断区，并明确标注不作为答案依据。诊断文本转义后显示，不进入会话历史，不保存整份失败草稿。

## 本地验证

- `tests/test_answering.py`：格式误判、资料限制、真正漏引、跨块借用、表格和虚构页码。
- `tests/test_streaming.py`：使用开国大典问题的本地模拟回答验证同步/流式一致；合法回答无需重试，真实漏引修复失败后返回具体诊断。
- `scripts/test-chat-ui.mjs`：模拟流降级后展示原因，文本转义、折叠展开、移动端和后续历史隔离；全部外部请求被阻断。

本次没有调用真实 DeepSeek 生成，因此这些结果不能证明该问题的线上回答已通过，也不能证明所有引用误判均已消除。
